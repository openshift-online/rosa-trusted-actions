# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

The ROSA Trusted Actions Server is a Chi-based HTTP API server implementing the ROSA Trusted Actions API. It is built from OpenAPI specifications using `oapi-codegen` for server code generation.

### Architecture Summary

**Core Components:**
- **API Server** (`cmd/server/`): Main application entry point with CLI flags (cobra), router setup (chi), and middleware chain
- **Handlers** (`internal/handlers/`): Implements the `ServerInterface` generated by oapi-codegen — all business logic goes here
- **Middleware** (`internal/middleware/`): HTTP middleware for structured logging, request IDs, and panic recovery
- **Configuration** (`internal/config/`): Loads application configuration from environment variables
- **Generated Code** (`internal/openapi/`): Server interface and types generated by oapi-codegen — **DO NOT EDIT**

**Key Details:**
- **Language**: Go 1.24
- **Module**: `github.com/openshift-online/rosa-trusted-actions-server`
- **Framework**: go-chi/chi v5
- **API spec**: OpenAPI 3.0 in `openapi/` (multi-file, bundled at build time)
- **Code generation**: `oapi-codegen` produces `internal/openapi/api.go` (committed, do not edit manually)
- **Logging**: `logrus` structured logging, injected via dependency injection
- **CLI**: `cobra` for server flags (`--listen-addr`, `--log-level`, `--log-json`)

**Key Directories:**
- `cmd/server/`: Main application
- `internal/handlers/`: API handler implementations
- `internal/middleware/`: HTTP middleware
- `internal/config/`: Configuration loading
- `internal/openapi/`: Generated code (DO NOT EDIT)
- `openapi/`: OpenAPI 3.0 spec source files (paths, components, schemas)
- `scripts/`: Helper scripts
- `docs/`: API documentation (ReDoc)

**Critical Invariants:**
- All secrets must come from environment variables, never hardcoded
- Generated code in `internal/openapi/` must never be edited manually
- `node_modules/` is for OpenAPI tooling only, never committed

## Development Commands

### Build
```bash
make build              # Bundle spec, generate code, compile binary
make build-linux        # Cross-compile for Linux
```

### Lint
```bash
make lint               # Run golangci-lint with project config
make fmt                # Format code (go fmt + goimports)
pre-commit run --all-files  # Run all pre-commit hooks
```

### Test
```bash
make test               # Run unit tests
make test-race          # Run with race detection
make test-coverage      # Generate coverage report
make test-integration   # Start server and run API tests
```

### Code Generation
```bash
make generate           # Bundle OpenAPI spec + generate Go code
make validate-spec      # Validate OpenAPI specification

```

```bash
make run                # Run server locally on :8080
make dev                # Run with auto-reload (requires air)
```

### Clean
```bash
make clean              # Remove build artifacts
make clean-all          # Remove everything including node_modules
```

## Agent Rules

### Agents MUST

**Prefer minimal diffs:**
- Make focused, incremental changes
- Avoid reformatting unrelated code
- Don't introduce abstractions unless necessary
- Three similar lines is better than premature abstraction

**Preserve coding style:**
- Follow existing patterns in the file/package
- Use stdlib `testing` with `httptest` for tests (no test frameworks)
- Use `logrus` for structured logging
- Follow standard Go formatting (gofmt)
- Import ordering: stdlib, external, then local (`github.com/openshift-online/rosa-trusted-actions-server/...`)

**Reuse existing abstractions:**
- Check existing handler patterns in `internal/handlers/`
- Follow middleware patterns in `internal/middleware/`
- Use existing config patterns in `internal/config/`
- Don't reinvent common operations

**Run targeted validation first:**
```bash
# After code changes, run in this order:
go build ./...                     # Fast compile check (5s)
go test ./internal/changed-pkg     # Affected tests (10s)
pre-commit run                     # Staged files only (15s)
make test                          # Full suite before commit (60s)
```

**Avoid broad refactors unless requested:**
- Fix the specific issue, not surrounding code
- Don't cleanup unrelated files
- Don't rename unless it fixes a bug
- Don't optimize unless there's a performance issue

**Avoid editing generated files:**
- Never edit `internal/openapi/api.go` — regenerate with `make generate`
- Never edit `go.sum` without changing `go.mod`
- Never edit files in `node_modules/`

**Avoid changing lockfiles unnecessarily:**
- Only modify `go.sum` when adding/updating dependencies
- Run `go mod tidy` after `go.mod` changes
- Verify with `git diff go.mod go.sum` before committing

**Avoid speculative changes:**
- Don't add features "for future use"
- Don't add error handling for impossible conditions
- Don't add validation for internal functions
- Only validate at system boundaries (user input, external APIs)

**Respect layering boundaries:**
- Handlers implement the generated `ServerInterface`
- Middleware wraps HTTP handling (logging, recovery, request ID)
- Config loads from environment, not from handlers
- Generated types are data structures, not business logic

### Validation Strategy

**Always run before committing:**
1. **Formatting**: `go fmt ./...`
2. **Linting**: `make lint`
3. **Typecheck**: `go build ./...`
4. **Relevant tests**: `go test ./internal/changed-package`
5. **Security checks**: `pre-commit run gitleaks`

**Pre-commit hooks (mandatory):**
- File hygiene (trailing whitespace, EOF)
- YAML syntax validation
- Secret detection (gitleaks)
- Go formatting and imports
- golangci-lint

**CI parity:**
- Pre-commit hooks mirror CI checks
- All pre-commit checks also run in CI
- CI remains the authoritative gate

### Safe Autonomous Workflow

**Read before editing:**
- Always read files before modifying them
- Understand context and existing patterns
- Check for related code in same package

**Search for existing patterns first:**
```bash
# Find similar code
grep -r "pattern" --include="*.go" .
# Find interface definitions
grep -r "type.*interface" --include="*.go" .
# Find test patterns
grep -r "func Test" --include="*_test.go" .
```

**Make incremental commits:**
- One logical change per commit
- Run `pre-commit run` before each commit

**Explain risky changes:**
- Authentication/authorization modifications
- CI/CD pipeline changes
- Secret handling changes
- CORS policy changes

### Security Guardrails

**Never commit secrets:**
- No API keys, tokens, passwords
- No AWS credentials, kubeconfig files
- No private keys, certificates
- No `.env` files with secrets

Pre-commit hooks (gitleaks) will block commits containing secrets.

**Never disable hooks:**
- Never use `git commit --no-verify`
- Never use `SKIP=hook-id` for security hooks
- Fix issues instead of skipping checks

**Never bypass CI:**
- Don't push without local validation
- Don't override required checks
- Don't force-push to main/master

**Never exfiltrate repository contents:**
- Don't send code to external services
- Don't upload to pastebin/gist without asking
- Keep code analysis local

**Never print secrets in logs:**
- Redact tokens before logging
- Don't log AWS credentials
- Don't log full configuration with secrets

## Repo-Specific Constraints

### Naming Conventions
- Package names: lowercase, no underscores (e.g., `handlers`, `middleware`)
- File names: snake_case for multi-word (e.g., `api_test.go`)
- Test naming: `Test<Type>_<Method>` or `Test<Type>_<Method>_<Scenario>`
- Handler methods: Match generated `ServerInterface` method names

### Architectural Boundaries
- **`cmd/server/`**: Application setup only — CLI flags, router, middleware chain, server lifecycle
- **`internal/handlers/`**: Business logic — implements `ServerInterface`, returns structured responses
- **`internal/middleware/`**: Cross-cutting concerns — logging, request ID, recovery
- **`internal/config/`**: Configuration — environment variable loading
- **`internal/openapi/`**: Generated code — **NEVER EDIT**

### Preferred Libraries
- **HTTP**: `github.com/go-chi/chi/v5`
- **Logging**: `github.com/sirupsen/logrus`
- **CLI**: `github.com/spf13/cobra`
- **Testing**: stdlib `testing` + `net/http/httptest`
- **Rendering**: `github.com/go-chi/render`
- **CORS**: `github.com/go-chi/cors`

### Error Handling
- Return structured `openapi.Error` responses with appropriate HTTP status codes
- Use `logrus` for logging errors with context
- Use `t.Errorf` for non-fatal test assertions, `t.Fatalf` for preconditions

## Code Generation Dependencies

After modifying API types or OpenAPI spec files, regenerate code:

```bash
make generate
```

**What this generates:**
- Server interface and types from OpenAPI spec → `internal/openapi/api.go`
- Bundled OpenAPI spec → `api-spec.yaml` (gitignored)

**When to regenerate:**
- After changing any file in `openapi/` directory
- After modifying `oapi-codegen.yaml`
