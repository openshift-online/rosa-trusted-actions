# Claude Code Hooks

Security and validation hooks for ROSA Trusted Actions Server development.

## Overview

This repository uses **pre-commit** for quality checks and validation. Claude Code hooks provide immediate feedback during development.

## Architecture

```text
┌─────────────────────────────────────┐
│   Developer / Claude Code Agent     │
└──────────────┬──────────────────────┘
               │
               ▼
┌─────────────────────────────────────┐
│   Pre-Edit Hook                     │
│   - Blocks generated file edits     │
│   - Warns on high-risk files        │
└──────────────┬──────────────────────┘
               │
               ▼
┌─────────────────────────────────────┐
│   Pre-Commit Hooks                  │
│   - golangci-lint (static analysis) │

               ▼

│   Git Commit                        │
└──────────────┬──────────────────────┘
               │
               ▼
┌─────────────────────────────────────┐
│   CI/CD (Tekton Pipelines)          │
└─────────────────────────────────────┘
```

## Available Hooks

### [pre-edit.sh](./pre-edit.sh)
**Purpose**: Prevent editing generated files and warn about high-risk changes

**Checks**:
- Generated OpenAPI code (`internal/openapi/`)
- Vendored code (`vendor/`)
- Node modules (`node_modules/`)
- High-risk files (CI workflows, Dockerfiles)
- Lock files (`go.sum`)

**Manual Usage**:
```bash
.claude/hooks/pre-edit.sh path/to/file.go
```

## Pre-Commit Configuration

This repository uses `.pre-commit-config.yaml` with:

### Hooks
1. **File hygiene** (<2s) — trailing-whitespace, end-of-file-fixer, check-yaml, check-merge-conflict
2. **Secret detection** (<5s) — gitleaks
3. **Go formatting** (<5s) — go-fmt, go-imports
4. **Go validation** (<10s) — go-vet, go-unit-tests
5. **Static analysis** (<15s) — golangci-lint

## Setup

### Prerequisites
```bash
# Install pre-commit
pip install pre-commit

# Install git hooks
pre-commit install
```

### Usage

```bash
# Run all checks on staged files
pre-commit run

# Run all checks on all files
pre-commit run --all-files

# Run specific check
pre-commit run gitleaks
pre-commit run golangci-lint
```

## Hook Categories

### Pre-Edit Hooks
**Purpose**: Validate before file modifications

**Current**:
- `pre-edit.sh`: Block edits to generated/vendored files

### Pre-Commit Hooks
**Purpose**: Validate before git commit

**Managed by**: pre-commit (configured in `.pre-commit-config.yaml`)

## Security Guardrails

### Secret Prevention
**Implementation**: gitleaks via pre-commit

**Configuration**: `.gitleaks.toml`

**Detects**:
- AWS credentials
- GitHub tokens
- API keys
- Private keys
- High-entropy secrets

**Action**: BLOCK commit

### Generated File Protection
**Implementation**: pre-edit.sh

**Detects**:
- `internal/openapi/` (generated by oapi-codegen)
- `node_modules/`

**Action**: BLOCK edit (suggest regeneration)

## Hook Performance

**Targets:**
- Pre-commit: <30s on typical changeset
- Individual checks: <10s each

**Optimization:**
- Hooks run fastest-first
- Only check changed files where applicable

## Troubleshooting

### Hook Not Running
```bash
# Verify pre-commit is installed
pre-commit --version

# Reinstall git hooks
pre-commit install

# Check hook configuration
cat .pre-commit-config.yaml
```

### Hook Fails Incorrectly
```bash
# Run hook manually for debugging
pre-commit run <hook-id> --verbose

# Update hooks
pre-commit autoupdate
```

### Hook Failures (DO NOT Bypass)

**NEVER bypass hooks:**
```bash
# FORBIDDEN
git commit --no-verify

# FORBIDDEN
SKIP=hook-id git commit
```

**If hooks are blocking your commit:**
1. **Investigate and fix the root issue** — hooks catch real problems
2. **If the hook or config is broken:**
   - Fix the hook/config first
   - Open an issue documenting the problem
3. **Re-run full validation:**
   - `pre-commit run --all-files` locally
   - Ensure all required CI checks pass

**Security hooks (gitleaks) must NEVER be bypassed under any circumstances.**
